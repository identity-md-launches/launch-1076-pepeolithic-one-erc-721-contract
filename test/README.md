# Tests

Run `forge build`, `forge test`, `forge fmt --check`, then
`python3 script/check_launch.py` from the repository root. No network, keys,
environment variables, FFI, fork, or filesystem cheatcodes are used by the tests.

`PepeolithicMainnet.t.sol` tests the exact launch parameters on chain ID 1,
including construction without ZTO code and with reverting recipients. It checks
both constructor mint events, all seven labels, all round boundaries, rational
halving segments at the actual prices, the maximum 147-round doubling ladder,
floor-sale exclusion, the latest line-sale update, all 400 sale pieces and 335
leftovers, complete issuance, all 735 ordinary metadata paths, endpoint metadata,
every cave's freeze permissions, sorted seat proofs, release timing, and payment
failure rollback. `support/MainnetSetup.sol` contains only explicit static launch
values and local mock setup.

`Pepeolithic.t.sol`, `PepeolithicProperties.t.sol`,
`PepeolithicInvariant.t.sol`, and `support/PepeolithicSetup.sol` retain the pinned
reference's tests with names changed. Their alternate coin, recipients, prices,
labels and compressed schedule are test fixtures, not mainnet deployment values.
They exercise custom constructor arguments, full-width arithmetic, all 335 seat
claims, invalid/duplicate proofs, exhausted inventory, batched sweeps, payment
false/revert/missing-bool paths, allowance failures, receiver rejection, nested
purchases, approvals, transfers, royalties, and events.

Four property tests each run 1,000 fuzz cases. A further monotonic-price property
runs 256 cases. The invariant campaign runs 256 sequences of 128 operations with
eight buyers and separate ghost accounting for piece ownership, balances, sale
counts, claims, payments, freezes and release. After each sequence it sweeps
unsold sale pieces and buys all remaining free pieces, verifies every owner and
the 737-piece cap, then retries exhausted operations. A deterministic handler
test ensures every operation is reachable. Tests use isolated EVM state and can
run in parallel or in any order.

The production Merkle wallet list was not supplied. The exact production root is
tested as a constructor value; successful membership tests use known local trees.
Mocks cannot establish live ZTO behavior. The no-custody invariant covers payments
generated by the protocol, not unsolicited transfers into the contract.

`PepeolithicAdversarial.t.sol` adds 128 randomized full-week scenarios against a
forward ladder model. Expected openings and payments are derived from the brief,
never from the contract's quote or last-sale getters. The model exercises quiet
rounds, floor-only purchases, purchases at opening and intermediate times,
multiple descending-price sales, rejected payments, sold-out rounds, and all six
cave transitions. A weighted average of adjacent halving knots supplies an
independent price oracle, including integer rounding. Two further properties run
1,000 cases each across every validated cave/round API, including full-width
invalid inputs. Deterministic tests cover maximum indices, claims after token
transfers, fixed admin rights and royalties after endpoint transfers, and seven
distinct bases frozen before the relevant pieces are minted.

`PepeolithicCallbacks.t.sol` uses a local ZTO mock with independent outer and
nested payment outcomes. Its eight tests enforce these rules:

- A false return or revert from the outer payment undoes both purchases, both
  payments and allowances, the opening/last-sale state, and any shared cursor or
  claim flag changed by a nested callback.
- A caught inner payment failure leaves exactly the outer purchase committed;
  its next sale piece remains available for a later buyer.
- Reentry cannot reuse the final sale slot or allocate a 336th free piece.
- Mint ownership is visible before the coin call, and nested successful buys
  emit their `Transfer` and `Bought` events once, in execution order.

The existing stateful campaign additionally checks remaining allowances against
ghost spending and the free-piece cursor against its independent allocation
queue after every operation. All added tests run offline with the already
vendored dependencies; none requires production Merkle proofs or token code.

`script/check_launch.py` checks the exact 16 manifest arguments against the compiled
constructor ABI, all seven label encodings, source fidelity to the pinned reference,
absence of unresolved links, runtime size below 9,000 bytes, and the supplied
protected check's literal forbidden-opcode scan. It uses Python's standard library.

Foundry lint warnings are reviewed rather than suppressed: timestamp comparisons
implement the required schedule; `_mint` is required to avoid receiver callbacks;
the character casts are bounded by validated piece indices; local counters use
Solidity's zero initialization. The event warning at `Bought` does not identify an
external call preceding the event: `_mintPiece` uses `_mint`, with no receiver call,
and `_pay` runs last. Slither and Mythril are not installed and were not run.
